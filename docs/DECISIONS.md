# DECISIONS log

| # | Decision | Why | Alternatives rejected |
|---|---|---|---|
| D-01 | **GitHub Actions** as CI/CD platform | Repo already on GitHub; environments, OIDC, attestations, GHCR built-in; free for public repos | GitLab CI (would need mirroring) |
| D-02 | **3 separated pipelines**: CI (`ci_*.yml`, in auto-monitor), CDL delivery and CDP deployment (`cdl_*.yml`, `cdp_*.yml`, in auto-monitor-deployment) | Separation of duties: developers own CI, cannot weaken delivery/deployment gates | One big workflow in the app repo |
| D-03 | One reusable workflow per stage, orchestrated by `*_main.yml` | Each stage reviewed/owned/tested alone; clear evidence per stage | Monolithic YAML |
| D-04 | Semgrep for SAST | Multi-language (Java, Python, TS), fast, SARIF output | CodeQL (slower, Java build needed) |
| D-05 | Trivy **binary** pinned + sha256 instead of `trivy-action` tag | trivy-action tags were hijacked in March 2026 (CVE-2026-33634) | Mutable action tags |
| D-06 | All third-party Actions pinned by **full commit SHA** | Tags can be moved; SHAs cannot | `@v4` tags |
| D-07 | Severity policy: CRITICAL (fixable) blocks app/image; HIGH+CRITICAL blocks IaC | Block what is exploitable and fixable without stopping all work | Block everything HIGH (too many false alarms on deps) |
| D-08 | Gitleaks + Trivy for secrets, exceptions stored in the **deployment repo** | Devs cannot self-approve exceptions; Gitleaks decodes base64 (found the test key Trivy missed) | `gitleaks:allow` inline comments (ignored on purpose) |
| D-09 | Terraform target = AWS (VPC, ALB+WAF, EC2, RDS×2, S3, KMS, OIDC) — **validated & scanned, not applied** | No cloud account/budget for the lab; scanning happens before apply anyway | Applying to a real account |
| D-10 | Registry = **GHCR**, images referenced by **digest**, signed provenance attestation | Immutable, verifiable, free; no long-lived registry password (job token) | Docker Hub + password secret |
| D-11 | Deployment target = fresh GitHub-hosted VM per run (option: self-hosted runner) | Real `docker compose` deployment + health checks without a cloud bill | Manual SSH deploy |
| D-12 | Secrets as **environment secrets** (staging ≠ production), generated by script | Only the env-bound job can read them; rotation = rerun script | Repo-level secrets (visible to every job) |
| D-13 | Python versions resolved by `pip freeze` before SCA | `requirements.txt` uses ranges → invisible to scanners | Ignoring the agent |
| D-14 | Compose start-up fix (agent depends on backend `service_started`) | Removes a deadlock found in M1 | — |
